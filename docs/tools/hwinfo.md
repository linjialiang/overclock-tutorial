# HWiNFO

HWiNFO 是这套流程里的"仪表盘"：它不制造负载，只负责把频率、电压、温度、功耗实时读出来，并记住每一项的最小值、最大值与平均值。判断"频率有没有掉、电压到底是多少"，看的就是它。

## 它能做什么

官方把它定位成硬件分析与监控的一体化工具 `[官方页]`：

| 能力 | 官方描述 |
|---|---|
| 硬件信息 | 按层级展开到每个部件的详细参数，可导出成硬件清单 |
| 实时监控 | 覆盖 CPU、GPU、主板、硬盘、外设等参数，用于发现过热、过载、性能下降或故障征兆 |
| 报告导出 | 可导出 XML、CSV、HTML；监控数据可用表格、曲线、托盘图标与 OSD 呈现 |
| 告警 | 对任意被监控参数设置自定义告警动作 |

## 界面与关键读数

![HWiNFO 传感器窗口：左列为当前/最小/最大/平均，行按 CPU、DTS、Enhanced、C-State、内存时序、主板与硬盘分组；顶部「传感器」组把关键项聚在一起](/tools/hwinfo/sensors.png)

| 列 | 含义 | 用法 |
|---|---|---|
| `当前`（Current） | 采样瞬间的读数 | 看实时变化 |
| `最小`（Minimum） | 自上次重置以来的最低值 | 判断空闲电压、最低频率 |
| `最大`（Maximum） | 自上次重置以来的最高值 | **判断温度/电压峰值就看这一列** |
| `平均`（Average） | 自上次重置以来的平均值 | 判断长期水平，避免被瞬时尖峰误导 |

分组按部件排列，本机能看到的几组 `[本机]`：

| 分组 | 里面有什么 |
|---|---|
| `CPU [#0]: Intel Core i7-4790K` | 核心 VID、核心频率、总线频率、Uncore 频率、核心有效频率、各核心 VID |
| `CPU [#0] ... : DTS` | 核心温度、核心距离 Tjmax 的差值、CPU 封装温度、核心最大值 |
| `CPU [#0] ... : Enhanced` | CPU 封装/IA/GT 频率与功率、PL1/PL2 功率限制、VR VCC 功率与温度 |
| `... C-State 驻留率` | 各 C-State 的驻留百分比，看空闲降频是否正常 |
| `内存时序` | 内存频率、倍频、tCas、tRcd、tRp、tRAS、tRC、tRFC、Command Rate |
| 主板厂商组（本机 `ASUS Z97-AR`） | 各温度探头 T1/T2/Temp1~4 |
| `主板` | +VCCIN、+3.3 V、+5 V、+12 V、VCCIO、VCCSA 与 CPU 核心电压 |
| `S.M.A.R.T.` | 每块硬盘的状态与温度 |

读超频结果时，重点盯这几行：

| 想看什么 | 找哪一行 | 判断 |
|---|---|---|
| 频率有没有掉 | `核心频率` 与 `核心有效频率` | 两者接近说明没被节流；有效频率明显低就是掉了 |
| 实际电压是多少 | 面板里的实际电压行（本机在 `主板` 组，如 `CPU 核心电压`、`Vcore0`），**不是 `核心 VID`** | VID 是 CPU 请求值，实际电压行才是核心拿到的 |
| 散热够不够 | `核心温度`、`核心距离 Tjmax 的差值` | 差值越小越接近温度墙 |
| 功耗压力 | `CPU 封装功率`、`IA 核心功率` | 对照散热与电源余量 |
| 内存有没有跑在目标档 | `内存频率`、`tCas`、`tRcd` | 本机 1200 MHz 与 [CPU-Z](/tools/cpuz) 内存页完全一致，可交叉验证 |

**最小/最大/平均不是"当前值的历史记录仪"**：它们从上次重置算起，测完一轮后看最大值才有意义。开始新一轮测试前先重置，否则会混进上一轮的数据。

## 设置里值得看一眼的几项

![HWiNFO 传感器设置 → 常规：左侧为轮询周期与平均间隔，中间为显示值与显示列，右下为传感器记录（CSV 输出）](/tools/hwinfo/settings.png)

| 项 | 本机默认 | 说明 |
|---|---|---|
| `轮询周期`·全局 | 2000 ms | 读数刷新间隔，越短越细，也越占资源 |
| `磁盘 SMART` / `嵌入式控制器` | 每 100 / 每 1 周期 | 这两类读数不走全局周期 |
| `平均间隔` | 0 样本 | 0 = 从运行开始累计到用户重置，这就是 `平均` 列的算法 |
| `温度单位` | 摄氏度 | 与教程里所有温度口径保持一致 |
| `显示值` | 温度、电压、功率、频率已勾；风扇、电流、使用率未勾 | 取消勾选会隐藏整类传感器 |
| `显示列` | 当前 / 最小 / 最大 / 平均 / 分析时间 | 勾掉哪列，窗口里就不显示哪列 |
| `传感器记录`·输出格式 | CSV | 长测留证时打开，配合日期格式与记录时间限制 |

**看不到风扇转速或电流，先来这里确认**：本机的「风扇」「电流」默认没有勾选，所以窗口里不显示，不是传感器缺失。`显示列` 里还可以把 `分析时间` 关掉，窗口会更清爽。

需要留证时，把 `传感器记录` 的 `启用切换热键` 勾上并指定快捷键，输出格式选 `CSV`，再用 `记录时间限制` 控制时长。

## 操作步骤

1. 解压便携包，运行对应架构的 `HWiNFO64.exe`（64 位系统）。
2. 打开传感器窗口（标题栏含"传感器状态"），把它拉宽到能看见完整分组。
3. 先确认设置：`传感器设置 → 常规` 里的 `显示值` 与 `显示列` 决定你能看到什么，缺项多半是被过滤掉了。
4. 开始压力测试前，先重置最小/最大/平均值，再开始跑 [AIDA64](/tools/aida64) 或 [TestMem5](/tools/testmem5)。
5. 测试中观察 `最大` 列的温度与电压；测试结束再看 `平均` 列判断长期水平。
6. 需要留证时开启传感器记录，输出 CSV，或导出 HTML 报告 `[官方页]`。

## 常见误区

| 说法 | 事实 |
|---|---|
| "HWiNFO 显示的电压就是我在 BIOS 里设的值" | 显示的是读数，不是设定值；两者不一致很常见，见[电压与供电](/principles/02-voltage) |
| "VID 就是 Vcore" | VID 是 CPU 请求值，Vcore 才是实际值；案例 01 里两者只差 2 mV（1.262 V 与 1.264 V），但标称 1.20 V 与 1.24 V 的两次测试 VID、Vcore 完全相同 |
| "当前频率正常就说明没掉频" | 要看`有效频率`与最低值；瞬间掉频在`当前`列看不出来 |
| "监控软件能替代压力测试" | HWiNFO 只读不压，负载要由 AIDA64、TestMem5 这类工具制造 |

想看一个完整的读数记录长什么样，可以对照[案例 01](/cases/01-4790k-z97ar)：同一台机器上，标称 1.20 V 与 1.24 V 两组的 VID、Vcore、温度、功耗几乎一致。

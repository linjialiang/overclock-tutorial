# TestMem5

TestMem5（简称 TM5）是一个 Windows 下的内存压力测试工具：它持续向已分配的内存写入、读取并校验数据，数据在压力下翻转就记一次错误。它只回答一个问题——**按现在的内存状态完整跑完，会不会出错**。

本篇结构取自随附的《TestMem5 内存测试与日志判读》手册，但**每条结论都与官方仓库核对过**：与官方冲突的地方以官方为准，社区经验一律标注。

## 它能回答什么、不能回答什么

| 能回答 | 不能回答 |
|---|---|
| 当前内存状态下是否出现错误 | 具体是哪一根内存、哪一颗颗粒损坏 |
| 换单条、换插槽后问题是否复现 | CPU、电源或显卡是否完全正常 |
| 长时间运行后是否仍然稳定 | 未来任何场景都绝对不会出错 |

出现错误能证明"当前状态不稳"，但不能直接指出是哪一个部件。要定位到某一根内存，得靠下面的复测流程把变量缩小。

## 下载与版本

- 官方发布在 GitHub 的 `CoolCmd/TestMem5` 仓库，当前版本 **0.13.1**（2024-07-09），以 **7z 压缩包**发布，解压即用，不需要安装 `[官方页]`。
- 原始 0.12 版的作者是 Serj，现由 CoolCmd 维护修正；版本号可以看 `TM5.exe` 与 `TM5.dll` 的文件属性 `[官方页]`。
- 需要 **Windows 7 或更新**；程序只依赖同目录的 `TM5.dll` `[官方页]`。
- 官方说明：部分杀毒软件（含 Windows 自带）会误报，原因是程序用汇编编写、启发式分析误判，压缩包里没有病毒 `[官方页]`。

::: warning 必须用管理员权限
官方明确建议以管理员身份运行；并说明**如果当前账号属于 Administrators 组，程序只能以管理员身份启动** `[官方页]`。右键 `TM5.exe` → 以管理员身份运行，否则内存分配不完整、日志也可能写不出来。
:::

## 界面与关键读数

![TestMem5 0.13.1 主界面：上方为配置名与内存/线程读数，中间 Status 一行是 0–15 的测试块进度，下方为已用时间、循环、Errors、剩余时间与 Test 1/31，底部是日志窗](/tools/testmem5/main.png)

| 位置 | 字段 | 含义 |
|---|---|---|
| 顶部 | `Configuration` | 当前配置名，必须和你想测的那套一致 |
| 左列 | `Tested, MB` | 本次实际测试的内存量（不是总容量） |
| 左列 | `CPU threads` / `Used threads` | 可用线程数与实际使用线程数，一般用自动 |
| 右列 | `Free, MB` / `Uncommitted, MB` | 测试期间留出的空闲内存与未提交内存 |
| 右列 | `Pages per second` | 每秒处理的页数，反映压力强度 |
| 中部 | `Status` 0–15 色块 | **当前循环里的测试块进度，不是错误数** |
| 下部 | `Elapsed` / `Remaining` | 已用时间与剩余时间；剩余时间由"至少测试时间"决定 |
| 下部 | `Cycle` | 已完成循环数 |
| 下部 | `Errors` | **唯一判据**，必须始终为 0 |
| 下部 | `Test 1 / 31` | 当前是第几个测试块、共几个（与配置有关） |
| 底部 | `Settings` / `Log` | 打开设置页、查看本次日志 |

两条容易误读的：`Status` 色块和 `Test x/31` 都是进度，不是错误；`Remaining` 到 0 之后程序还会等当前循环跑完，所以实际结束时间可能略晚 `[官方页]`。

## 五步完成一次测试

1. **解压并启动**：右键 `TM5.exe` → 以管理员身份运行。程序**启动后自动开始测试**，界面上没有单独的 Start 按钮。
2. **打开设置**：点 `Settings`，切到测试相关标签页；这里决定配置方案、最短时长、线程数与错误停止条件。
3. **选配置**：不知道怎么选就保持默认的 `Universal 2 @ LMhz`——官方从 0.13 起把它设为默认配置，替换了旧的 `MT.cfg` `[官方页]`。
4. **设停止条件**：错误停止数设为 **1**，出现第一个错误立即停，避免继续跑下去扩大风险。官方说明默认行为就是"第一个错误后停止" `[官方页]`。
5. **等待并读结果**：先看 `Errors` 是否为 0，再点 `Log` 确认配置名与结束状态。

时长以**分钟**为单位，不是固定循环数；时间到期后程序会等当前循环结束 `[官方页]`。这也是它比"跑满 N 轮"更好理解的地方。

## 配置方案怎么选

官方压缩包内置了这些配置文件（文件名即配置正式名称）`[官方页]`：

| 配置文件 | 适用内存 | 用途 |
|---|---|---|
| `Universal 2 @ LMhz` | DDR3 / DDR4 / DDR5 | **官方默认配置**，第一轮首选 `[官方页]` |
| `Super Light 2 @ anta777` | 全平台 | 快速自检、时间不够时用 `[经验]` |
| `Heavy @ anta777` | DDR4 / DDR5 | 长时间压力测试 `[经验]` |
| `Extreme @ anta777` | DDR4 / DDR5 | 第二轮加强 `[经验]` |
| `Absolut @ anta777` | DDR4 / DDR5 | 深度长测、最终复核 `[经验]` |
| `Default @ serj` | 全平台 | 轻量基础检查 `[经验]` |
| `1usmus v3 @ 1usmus` | DDR4（DDR3 可试） | 第一次摸底 `[经验]` |
| `DDR5 Intel @ anta777` | **仅 Intel DDR5** | DDR5 专用加强 `[经验]` |
| `DDR5 Ryzen3D @ anta777` | **仅 AMD DDR5（3D 缓存平台）** | DDR5 专用加强 `[经验]` |

选择规则只有三条：

1. **先按内存代数排除**：DDR3/DDR4 机器不要选两个 DDR5 专用配置。
2. **首测用默认配置**：`Universal 2 @ LMhz` 覆盖三代内存，先回答"有没有明显错误"。
3. **再按平台加强**：确认平台与代数后，再用对应的 anta777 配置做第二轮。

上表只有"默认配置"和"文件名"来自官方，各配置的强度与适用平台属于社区经验 `[经验]`；如果你手上的配置版本不同，名字可能带版本后缀，属正常现象。

## 怎样才算通过

| 本次结果 | 结论 | 下一步 |
|---|---|---|
| 完整跑完计划时长，`Errors = 0` | 本轮通过 | 延长时长复测，或进入下一项测试 |
| 出现任意 1 个 `Error` | 本轮失败 | 保存日志，同配置复现，再试单条/换槽 |
| 中途关闭、蓝屏、卡死、只有半截日志 | **不算通过** | 排除后台干扰，重新完整跑一遍 |

`Errors = 0` 只能证明"在这次测试覆盖的场景和时长内没发现错误"，它是稳定性证据，不是永久健康保证。结论要写成有边界的句子：

> 在这台机器、当前内存状态下，TM5 连续跑完 180 分钟且 0 Errors，日常使用一周无异常。

时长怎么安排：默认配置的最短时间就是 90 分钟（本机界面剩余时间显示 `1:29:54`）`[本机]`；把它延长到 180 分钟或更长属于经验做法 `[经验]`，容量越大跑完一轮越久，但判据不变。

## 日志怎么看

日志有两个入口：主界面 `Log` 按钮，以及 `TM5.exe` 同目录的 `Log.txt`（日志与设置都保存在程序目录）`[官方页]`。设置里可以限制日志大小甚至禁止写入，**排查问题时不要关**，否则没有复盘证据 `[官方页]`。

一段日志只有四类信息：

| 段落 | 你会看到 | 怎么用 |
|---|---|---|
| 测试信息 | 版本、配置名、测试内存量、线程数 | 确认是不是你要测的那一组 |
| 运行信息 | 已用时间、当前测试块、循环编号 | 确认测试是否真的在推进 |
| 错误信息 | `Error`、错误码、地址、期望/实际数据 | 出现任意一条就判失败 |
| 结束信息 | 正常完成、用户中断、程序错误 | 判断这一轮是否完整结束 |

下面这段日志来自本机的一次真实运行 `[本机]`：

```text
-------- TestMem5 0.13.1 2026-11-26 19:06 --------
0:00:00  Configuration: Universal 2 @ LMhz
0:00:00  Testing 2768 MB x 8 (68%) out of 32452 MB
0:16:45  Testing stopped by user
```

读法是三步：**先核对配置名**（是不是这次要测的方案）→ **再搜 `Error`**（有就判失败，不用逐个研究错误码）→ **最后看结束状态**（是正常结束还是被打断）。错误码的含义随配置、平台和版本变化，对普通用户来说结论只有一句：出现错误，当前状态就不稳定。

## 复测与记录

出现错误不等于内存条报废，也可能是频率/时序不稳、两条组合不兼容、插槽接触不良或内存控制器问题。按顺序缩小变量：

| 步骤 | 做什么 | 怎么判断 |
|---|---|---|
| 1 先复现 | 同一配置再跑一次 | 错误再次出现才值得继续排查；偶发一次也不能算正常 |
| 2 单条 + 换槽 | 只插一根，逐条测，并交换插槽 | 单条在多槽都报错 → 硬件嫌疑大；只有双条组合报错 → 兼容/设置问题 |
| 3 换机验证 | 把内存装到另一台正常机器 | 多平台都报错，才更接近"内存本身有问题" |

留证时至少保存：配置名称、内存代数与容量、错误行、完整结束状态。建议用下面这张表记录：

| 日期 | 内存 | 方案 / 时长 | 循环 | Errors | 结论 |
|---|---|---|---|---|---|
| 11-26 | DDR3 4×8 GB | Universal 2 / 90 min | 1 | 0 | 延长复测 |

## 与 MemTest86+ 的分工

TM5 在 Windows 内跑，快、方便、适合反复改参数后的快速筛查；[MemTest86+](/tools/memtest86plus) 从 U 盘启动、不依赖操作系统，能测到 Windows 占用的内存，适合做最终验证。两者判据一致：完整跑完且 0 Errors。

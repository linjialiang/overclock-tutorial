# CPU-Z

CPU-Z 是免费的系统信息工具，作用是在**动手之前先确认机器身份**：处理器型号与倍频、主板芯片组与 BIOS 版本、内存类型/容量/时序/SPD，以及实时的核心频率与内存频率。它不做压力测试，只负责"你现在测的到底是什么"。

## 它能报什么

官方对功能的描述是 `[官方页]`：

- 处理器名称与型号、代号、工艺、封装、各级缓存；
- 主板与芯片组；
- 内存类型、容量、时序，以及模组的 SPD 规格信息；
- 实时测量每个核心的内部频率与内存频率。

## 下载与版本

- 官方站点 `cpuid.com` 提供免费版，分为安装包（exe）与便携压缩包（zip），也有各主板厂商的定制版 `[官方页]`。
- 当前版本 3.02（2026-11），本文截图来自本机同版本中文界面 `[本机]`。

## 界面与关键读数

![CPU-Z 处理器标签：上方为名称、代号、插槽、工艺、核心电压与规格，下方为实时核心速度、倍频、总线速度与缓存信息](/tools/cpuz/cpu.png)

CPU-Z 的窗口是标签式的，常用的是前四个：

| 标签 | 回答什么 | 关键读数 |
|---|---|---|
| `处理器` | 这是什么 CPU | 名称、代号、插槽、工艺、`核心电压`、`核心速度`、`倍频`、`总线速度` |
| `主板` | 这是什么板子、什么 BIOS | 制造商、型号、芯片组、BIOS 版本与日期、微码 |
| `内存` | 内存现在跑在什么状态 | 类型、大小、`通道数`、`LLC/Ring`、`内存频率`、各项时序 |
| `SPD` | 内存条本身是什么规格 | 按插槽列出模块大小、最大带宽、制造商、`周次/年份`、型号与 JEDEC/XMP 档位 |

读法上有三个关键点：

1. **`核心速度` = `倍频` × `总线速度`。** 上面的截图里 `x47.0` × `100.00 MHz` = 4700 MHz，这就是"47x"的来历；数字每秒在变，是正常的节能与睿频行为。
2. **`内存频率`（英文界面叫 DRAM Frequency）是时钟频率，不是 DDR 的标称频率。** DDR 是 Double Data Rate，一个时钟周期传两次数据，所以标称值约等于它的 2 倍：`1200 MHz` 对应 DDR3-2400 这一档。
3. **`核心电压` 是当前读数，不等于 BIOS 里的设定值。** 想确认设定有没有生效，要配合 [HWiNFO](/tools/hwinfo) 看 Vcore 与 VID，方法见[电压与供电](/principles/02-voltage)。

### 内存标签

![CPU-Z 内存标签：上方为类型 DDR3、大小 32 GBytes、通道数 双通道、LLC/Ring 4000 MHz，下方为内存频率 1200 MHz 与各项时序](/tools/cpuz/memory.png)

| 字段 | 本例读数 | 说明 |
|---|---|---|
| `类型` / `大小` | DDR3 / 32 GBytes | 系统识别到的总容量，条数要看 SPD 页 |
| `通道数` | 双通道 | 插错槽位会退化成单通道 |
| `LLC/Ring` | 4000.0 MHz | 缓存总线频率，对应"Ring 40x"，见[缓存与 Ring](/principles/04-cache) |
| `内存频率` | 1200.0 MHz | 时钟频率，×2 才是 DDR3-2400 |
| `FSB:DRAM` | 1:9 | 分频比值，只作参考；判断频率以 `内存频率` 为准 |
| `CAS# 延迟 (CL)` 等 | 11 / 13 / 13 / 30 / 2T | 实际生效的时序，必须与 SPD 页对照 |

`FSB:DRAM` 是分频关系，不同平台算法不同，别拿它反推频率；判断内存跑在多少，只看 `内存频率` 这一行。

### SPD 标签

![CPU-Z SPD 标签：插槽选择、模块大小 8 GBytes、最大带宽 PC3-19200K、制造商 Apacer、周次/年份 43/18、XMP 1.3，下方为 JEDEC 与 XMP-2400 两组时序表](/tools/cpuz/spd.png)

| 字段 | 本例读数 | 说明 |
|---|---|---|
| `内存插槽选择` | 插槽 #1 | 四条内存要逐槽切换核对 |
| `模块大小` | 8 GBytes | 单条容量；4×8 GB = 32 GB 才对得上内存页的总量 |
| `最大带宽` | PC3-19200K (1200 MHz) | 带宽代号与时钟频率，19200 MB/s 即 DDR3-2400 |
| `SPD扩展` | XMP 1.3 | 是否带 XMP 档案、版本号 |
| `制造商` / `周次/年份` / `型号` | Apacer / 43/18 / 78.CAG38.23K0C | 核对四条是否同型号同批次 |
| 时序表 | JEDEC #4/#5/#6 与 XMP-2400 四列 | 左边几列是 JEDEC 标准档，最右是 XMP 档 |

时序表的读法：**JEDEC 列是标准档（不开 XMP 时按它跑），XMP 列才是厂商为超频档写的参数**。本例 JEDEC 依次是 685 / 761 / 800 MHz，XMP-2400 是 1200 MHz、11-14-14-30、2T、1.650 V。

## 怎么核对 XMP 有没有生效

这是 CPU-Z 最实用的场景：

1. 打开 `内存` 标签，记下 `内存频率` 与各项时序。
2. 打开 `SPD` 标签，切到对应插槽，找到最右侧的 XMP 列（本例 `XMP-2400`），记下它的频率与时序。
3. 两页对照：
   - `内存频率` 与 XMP 列一致（本例都是 1200 MHz）→ XMP 已生效；
   - `内存` 页停在 JEDEC 档（例如 800 MHz / DDR3-1600）→ XMP 没生效或被降频。

本例还有一处值得注意：`内存` 页的实际时序是 **11-13-13-30**，而 SPD 的 XMP-2400 列写着 **11-14-14-30**、1.650 V。频率对得上、时序却更紧，说明**当前生效的不是 XMP 原样档位**。要确认是被手动改过还是主板套用了别的参数，回 BIOS 看这几项是 Auto 还是固定值。**频率一致不等于参数完全等于 XMP**，两页都要看。

`SPD` 页还要逐个插槽核对 `模块大小` 与 `型号`，确认系统把每一条都识别成了同一规格——混插或某条没认到，会直接改变能跑到的频率与时序。

## 常见误区

| 说法 | 事实 |
|---|---|
| "CPU-Z 显示 4700 MHz，就说明一直在 4.7 GHz" | 显示的是瞬时读数；判断有没有掉频要看 [HWiNFO](/tools/hwinfo) 的有效频率与最小值 |
| "内存标称 2400，CPU-Z 只显示 1200，是不是被降频了" | `内存频率` 是时钟频率，×2 才是 DDR 标称值 |
| "CPU-Z 能测稳定性" | 不能，它没有压力测试；稳定性要用 [AIDA64](/tools/aida64)、[TestMem5](/tools/testmem5) 或 [MemTest86+](/tools/memtest86plus) |
| "BIOS 里设了 1.24 V，CPU-Z 显示 1.252 V 就是设置错了" | 读数与设定值本来就有偏差与掉压，判断要看趋势和满载值 |

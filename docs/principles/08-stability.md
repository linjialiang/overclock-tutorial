# 稳定性验证

超频的终点不是"能开机"，而是"在真实使用中不出错"。稳定性验证就是用不同负载、不同时长去逼近这个结论。本章的前提是[电源与散热](/principles/07-power-cooling)已经够用——散热不够时，看到的"不稳"可能只是温度问题。

## 什么才算稳定

1. 频率不下降（有效频率与核心频率一致）。
2. 无 WHEA、无计算错误、无蓝屏/重启、无驱动崩溃。
3. 组合负载、真实应用、冷启动与睡眠唤醒都通过。

任何一项不满足，只能叫"本轮未通过"。频率不掉、温度不高只是必要条件：它说明功耗墙和温度墙没拦住你，不代表算出来的结果正确。计算错误和校验失败比蓝屏更早暴露问题，蓝屏/重启是最后一道防线，不能当作"偶发"。

## 负载类型：一种通过不代表全稳

![图 1：CPU 负载压核心与缓存、FPU 与 AVX 负载压浮点单元和功耗、内存负载压内存控制器与内存条、组合负载让多单元同时抢功耗与散热；一种负载通过不代表全稳，验证顺序是单项到组合](/principles/08-load-types.svg)

- 四类负载的电流波形、电压跌落和温度都不同：CPU 通过不代表内存通过，内存通过也不代表 AVX 通过。
- 所以顺序是"从窄到宽"：先单项确认，再组合确认。

FPU/AVX 负载的发热和功耗通常高于普通 CPU 负载 `[经验]`，很多"日常没事、一跑就崩"的设置在这里暴露。

具体用哪个工具制造这些负载、读数在哪个窗口看，见[烤机工具](/tools/)：CPU 与组合负载用 [AIDA64](/tools/aida64)，内存用 [TestMem5](/tools/testmem5) 或 [MemTest86+](/tools/memtest86plus)，全程用 [HWiNFO](/tools/hwinfo) 记读数。

### 时长只扩大覆盖范围

| 时长 | 能说明什么 |
|---|---|
| 5~10 分钟 | 看温度曲线是否稳定、有没有立刻报错 |
| 20~30 分钟 | 短时热/功耗筛查 |
| 1 小时以上 | 覆盖更多状态切换和温度饱和 |
| 数小时 | 组合负载/内存长测 |

烤机是恒定负载，日常使用是负载不断切换；电压跌落、频率跳变、电源瞬态响应这些环节，在恒定负载里被绕过去了。所以真实应用和冷启动往往比多烤一小时更早暴露问题。

## WHEA：比蓝屏更早的信号

![图 2：WHEA 分 Corrected 已纠正与 Uncorrected 不可纠正；Event ID 18 通常是致命硬件错误，17 与 47 常见为已纠正或警告；Error Source 标出 Processor、Memory、PCIe；有内核转储时用 WinDbg 的 !whea 与 !errrec 查看](/principles/08-whea.svg)

WHEA（Windows Hardware Error Architecture）是 Windows 的硬件错误上报机制，同时覆盖可纠正/非致命错误，所以"有一条记录"不等于"这次超频失败"，要看严重度和是否复现 `[官方页]`。

- **Corrected（已纠正）**：硬件或固件已修正，非致命，系统继续运行；偶发的可纠正记录先排除驱动/固件因素。
- **Uncorrected（不可纠正）**：无法修正，通常导致蓝屏/重启。出现新增、不可纠正或可复现的 WHEA，视为不稳定。
- **Error Source** 会标出 Processor、Memory、PCIe 等来源；先按来源隔离（内存回默认、Cache 回 Auto），不要一看到 WHEA 就加 CPU 电压 `[官方页]`。
- **Event ID**：WHEA-Logger 的 18 通常表示致命硬件错误；17、47 常见为已纠正/警告，需按错误记录和是否复现判断 `[官方页]`。
- 能生成内核转储时，WinDbg 的 `!whea` 显示顶层 WHEA 信息，`!errrec <地址>` 显示指定 error record 的内容；普通排查看事件查看器通常够用 `[官方页]`。

没有 WHEA 只表示"没捕获到"，不等于绝对稳定。蓝屏是系统已经撑不住，WHEA 是硬件先举手，所以验证时要主动记录 WHEA 计数。

## 核心不稳 vs 缓存/Ring 不稳

![图 3：满载蓝屏与一跑 FPU 就错更像核心不稳，空闲轻载蓝屏与加载崩溃更像缓存/Ring 不稳；隔离手段是内存回默认、Cache 回 Auto 后复现，故障消失说明问题在缓存](/principles/08-core-vs-cache.svg)

图中是经验判据，不是官方错误分类；同一现象也可能由电压、温度或内存引起 `[经验]`。

- 核心怎么测：FPU 5–10 分钟看温度 → 20–30 分钟 → CPU + FPU + Cache + Memory 组合 → 真实应用/冷启动。核心不稳通常在高负载、高电流时暴露。
- 缓存怎么测：核心和 Cache 是两套倍频/电压，必须分开验证。先固定核心，只动 Cache Ratio，再用 `Stress cache` 与组合负载复测；完整步骤见[缓存与 Ring](/principles/04-cache)。

Cache 回 Auto 后恢复，说明问题更可能在 Cache；照样崩，问题更可能在核心、内存或供电。

## 记录的最小集合

| 项目 | 为什么记 |
|---|---|
| BIOS 版本 / 设置值 | 复现的前提 |
| 室温 / 散热器 | 温度结论的分母 |
| 频率 / 有效频率 | 判断有没有节流 |
| VID / Vcore / VCCIN | 区分请求值与实际值 |
| 封装温度 / 最高单核 | 散热是否够 |
| 封装功耗 | 电源/散热压力 |
| 测试软件与时长 | 结论的边界 |
| WHEA / 错误计数 | 稳定性的硬证据 |

这份清单的作用是让结论可复现。只写"稳了"没有意义——换个人、换个季节、换个 BIOS 版本，同一套设置可能是另一个结果。

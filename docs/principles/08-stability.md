# 稳定性验证

超频的终点不是"能开机"，而是"在真实使用中不出错"。稳定性验证就是用不同负载、不同时长去逼近这个结论。本章讲清楚判据、负载差别、时长的意义，以及怎么区分核心不稳和缓存不稳。本章的前提是[电源与散热](/principles/07-power-cooling)已经够用——散热不够时，看到的"不稳"可能只是温度问题。

## 什么才算稳定

1. 频率不下降（有效频率与核心频率一致）。
2. 无 WHEA、无计算错误、无蓝屏/重启、无驱动崩溃。
3. 组合负载、真实应用、冷启动与睡眠唤醒都通过。

任何一项不满足，只能叫"本轮未通过"，不能叫"稳定"。

> "频率不掉 + 温度不高"只是必要条件，不是稳定。频率不掉只说明没触发节流；CPU 仍可能算错、报 WHEA、在某个应用里崩溃。

这条误解值得单独强调：节流、温度和稳定性是三件事。没有节流、温度漂亮，说明**散热和功耗墙没拦住你**，不代表**算出来的结果是正确的**。

## 三类负载，外加组合

| 负载 | 主要压什么 | 能证明什么 |
|---|---|---|
| CPU 负载 | 核心、缓存 | 基础稳定性 |
| FPU / AVX 负载 | 浮点单元、功耗 | 高热、高功耗下的稳定性 |
| 内存负载 | 内存控制器、内存条 | 内存/IMC 稳定性 |
| 组合负载 | 多单元同时工作 | 更接近真实高负载 |

基本的三类是 CPU、FPU/AVX、内存；组合负载是把它们叠在一起跑，更接近真实高负载场景。

## 为什么一种通过不代表全稳

不同负载的电流波形、电压跌落、温度都不同；CPU 通过不代表内存通过，内存通过也不代表 AVX 通过。

具体到三类负载：

- **CPU 负载**主要给核心和缓存压力，电流相对平稳，最容易通过。
- **FPU / AVX 负载**的发热和功耗通常高于普通 CPU 负载 `[经验]`，对散热和电压的要求更苛刻，很多"日常没事、一跑就崩"的设置在这里暴露。
- **内存负载**压的是内存控制器和内存条，和核心电压关系不大；核心再稳，内存该错还是错。
- **组合负载**让多个单元同时抢功耗和散热，是最接近真实高负载的一档。

所以验证顺序是"从窄到宽"：先单项确认，再组合确认。

## 测试时长的意义

下表是经验时长，不是官方保证；覆盖的场景比单纯拉长更重要。

| 时长 | 能说明什么 |
|---|---|
| 5~10 分钟 | 看温度曲线是否稳定、有没有立刻报错 |
| 20~30 分钟 | 短时热/功耗筛查 |
| 1 小时以上 | 覆盖更多状态切换和温度饱和 |
| 数小时 | 组合负载/内存长测 |

时长不是越长越"绝对稳定"，而是覆盖更多场景。真实应用和冷启动往往比多烤一小时更能暴露问题。

原因很直接：烤机是**恒定负载**，而日常使用是负载不断切换。电压跌落、频率跳变、电源瞬态响应这些环节，在恒定负载里被绕过去了。所以"烤机 1 小时通过"只能说明"这一小时、这一种负载没问题"。

## 读数怎么读

- `WHEA`：硬件报告的错误。出现新增、不可纠正或可复现的 WHEA，视为不稳定；偶发的可纠正记录要先排除驱动/固件因素。
- 计算错误/校验失败：比蓝屏更早暴露问题。
- 蓝屏/重启：最后一道防线，不能当作"偶发"。

### WHEA 是什么

WHEA（Windows Hardware Error Architecture）是 Windows 的硬件错误上报机制。超频不稳时，CPU、内存、PCIe 的纠错或不可纠正错误会被记录成 WHEA 事件。它同时覆盖可纠正/非致命错误，所以“有一条记录”不等于“这次超频失败”，要看严重度和是否复现 `[官方页]`。

- 出现 WHEA 不一定是 CPU 电压不够，也可能来自内存、Cache 或 PCIe。
- 先隔离变量：内存回默认档、Cache 回 Auto，再复现。
- 没有 WHEA 只表示"没捕获到"，不等于绝对稳定。

看记录时先分清两个词：

- **Corrected（已纠正）**：硬件或固件已经修正，属于非致命错误，系统可以继续运行。
- **Uncorrected（不可纠正）**：系统无法修正，通常会导致蓝屏/重启。

记录里的 Error Source 会标出 Processor、Memory、PCIe 等来源；先按来源隔离，不要一看到 WHEA 就直接加 CPU 电压 `[官方页]`。

事件查看器里，WHEA-Logger 的 Event ID 18 通常表示致命硬件错误；17、47 常见为已纠正/警告，需按错误记录和是否复现判断 `[官方页]`。

### 进阶：用 WinDbg 看错误记录

如果系统能生成内核转储，WinDbg 的 WHEA 扩展可以读出错误记录：

- `!whea`：显示顶层 WHEA 信息。
- `!errrec <地址>`：显示指定 WHEA error record 的内容。

对普通超频排查，事件查看器里的来源、严重度、是否复现通常够用；WinDbg 适合进一步确认报的是 Processor、Memory 还是 PCIe `[官方页]`。

WHEA 的价值在于它比蓝屏更早、更细：蓝屏是系统已经撑不住，WHEA 是硬件先举手。所以验证时应该主动记录 WHEA 计数，而不是等系统崩了才回头找原因。

## 核心不稳 vs 缓存/Ring 不稳

下表是经验判据，不是官方错误分类；同一现象也可能由电压、温度或内存引起 `[经验]`。

| 现象 | 更像核心不稳 | 更像缓存/Ring 不稳 |
|---|---|---|
| 满载蓝屏/重启 | 常见 | 也可能 |
| 空闲/轻载蓝屏、随机重启 | 较少 | 常见 |
| WHEA | Processor Core / Cache 都可能 | Cache / 互连相关更多 |
| 应用崩溃/闪退 | 高负载时 | 轻载、切换、加载时 |
| 一跑 FPU 就错 | 典型 | 也可能 |
| Cache 回 Auto 后恢复 | 否 | 是（关键判据） |

### 核心怎么测

FPU 5–10 分钟看温度 → 20–30 分钟 → CPU + FPU + Cache + Memory 组合 → 真实应用/冷启动。核心不稳通常在高负载、高电流时暴露。

### 缓存怎么测

1. 先把核心频率和电压固定下来（核心已单独验证过），只动 Cache Ratio。
2. 用缓存专项测试单独跑 20–30 分钟 `[经验]`；再跑 `CPU + FPU + Cache` 组合。
3. 观察 WHEA、应用崩溃、空闲/轻载稳定性——缓存不稳常在轻载暴露。
4. 出问题把 Cache 回 Auto（或降回上一档）复测；能恢复就说明问题在 Cache。
5. 需要时小幅加 `CPU Cache Voltage`（+0.01–0.02 V），每次只改一项。

### 为什么缓存要单独测

核心和 Cache 是两套倍频/电压；核心稳不代表 Ring 稳，Ring 不稳也不一定在 FPU 里暴露。把 Cache 回 Auto 是最快的隔离手段。

反向也成立：Cache 回 Auto 后仍然出错，就不要继续在 Cache 上折腾，问题更可能在核心、内存或供电配置上。

## 记录的最小集合

| 项目 | 为什么记 |
|---|---|
| BIOS 版本 / 设置值 | 复现的前提 |
| 室温 / 散热器 | 温度结论的分母 |
| 频率 / 有效频率 | 判断有没有节流 |
| VID / Vcore / VCCIN | 区分请求值与实际值 |
| 封装温度 / 最高单核 | 散热是否够 |
| 封装功耗 | 电源/散热压力 |
| 测试软件与时长 | 结论的边界 |
| WHEA / 错误计数 | 稳定性的硬证据 |

这份清单的作用是让结论可复现。只写"稳了"没有意义——换个人、换个季节、换个 BIOS 版本，同一套设置可能是另一个结果。

## 本章要点

- 稳定要同时满足：频率不掉、无新增/不可纠正 WHEA、无计算错误、无蓝屏/重启、组合负载与冷启动都通过。
- "频率不掉 + 温度不高"只是必要条件，不能证明算出来的结果是对的。
- CPU、FPU/AVX、内存三类负载压的部位不同，一种通过不代表全稳，要按"单项 → 组合"的顺序验证。
- 烤机时长只扩大覆盖范围，不产生"绝对稳定"；真实应用和冷启动往往更早暴露问题。
- 核心和 Cache 是两套倍频/电压；把 Cache 回 Auto 是最快的隔离手段，恢复即说明问题在 Cache。

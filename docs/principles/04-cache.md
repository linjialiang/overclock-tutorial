# 缓存与 Ring

调完核心频率和内存之后，很多新手会忽略 CPU 里还有一条独立频率：缓存倍频，也就是 Ring。它不直接决定跑分，却常常是"核心明明没问题、机器偶尔蓝屏"的真正原因。本章讲清 Ring 连了什么、Cache Ratio 该设到多少、缓存电压怎么给，以及怎么把缓存和核心分开验证。

## Ring 连接什么

Ring（环形总线）是 CPU 内部的一条环状互连 `[Intel]`，把下面这些部件串在一起：

| 部件 | 与 Ring 的关系 |
|---|---|
| CPU 核心 | 通过 Ring 访问 L3 缓存和内存 |
| L3 缓存 | 挂在 Ring 上 |
| 内存控制器（IMC） | 挂在 Ring 上 |
| 集成显卡 | 挂在 Ring 上，与核心共用 |

Ring 的频率就是 BIOS 里的 Cache Ratio（缓存倍频）。所以它影响的不是"核心算得多快"，而是核心访问缓存和内存时"走得多快"：

- Ring 越高，核心访问 L3 与内存的延迟通常越低 `[经验]`。
- Ring 越高，功耗和温度也越高，并且会与核心抢散热。
- 与倍频一样，Cache Ratio 也是 BCLK × 倍频，100 MHz 基准下 40x 就是 4000 MHz。

改 Cache 倍频会牵动哪些量，可以对照下面这条链条：

| 你改的 | 直接变化 | 连带影响 | 先看什么 |
|---|---|---|---|
| Cache 倍频 ↑ | Ring ↑ | 功耗/温度 ↑，可能与核心抢散热 | 核心与 Cache 分别验证 |

## Cache Ratio 与核心频率的关系

核心倍频和缓存倍频是两套独立的设置，**不必完全相同**，但也不能差太多。

> ASUS ROG 的 Haswell 指南大意：追求绝对性能时，Ring 保持在核心频率 300 MHz 以内就足够；Ring 高于核心频率没有性能收益，建议与 CPU 倍频同步，或最多低 300 MHz。`[官方页]`

把这句话展开，就是四种典型设置：

| 设置 | 结果 |
|---|---|
| Ring = 核心 | 延迟最低，功耗与温度最高 |
| Ring = 核心 −300 MHz | 追求性能时的常见上限；日常可以先 Auto |
| Ring 远低于核心（如核心 47x、Ring 40x，差 700 MHz） | 多出明显的延迟差 `[经验]` |
| Ring > 核心（如核心 45x、Ring 47x） | 没有性能收益，只会更热 |

三条结论：

1. 差得太多（700 MHz 这种量级）不划算，多出来的延迟是白白丢掉的。
2. Ring 高于核心没有意义，只是额外发热。
3. 追求性能时，把 Ring 放在"核心 −300 MHz"到"核心同频"之间；日常使用可以先保持 Auto，确认核心稳定后再动它。

提升 Ring 的代价主要在功耗和温度：Ring 与核心共享同一套散热，Ring 越高，核心能用的温度余量就越少。收益则集中在缓存和内存的延迟上，不是所有应用都能感知——游戏帧数、加载时间比纯浮点跑分更容易体现出来。

## 缓存电压

缓存有自己的电压项，通常叫 `CPU Cache Voltage`，与核心电压是**两套独立设置**：

- 缓存电压作用于 CPU 的 uncore 部分（含缓存/Ring），不会自动帮核心加压，反之亦然；手册原文是 "voltage fed to the CPU uncores including its cache" `[手册]`。
- 不少主板的缓存电压提供 Auto / Manual / Offset 三种模式，Override 范围常见 0.001–1.920 V、Offset 范围常见 0.001–0.999 V `[手册]`。
- 具体到某一颗 CPU 需要多少缓存电压，没有官方推荐值，只能实测。

给电压的原则和核心一样：

1. **先从 Auto 起步**，只在确认缓存不稳之后才动它。
2. 每次只加 **0.01–0.02 V**，加完立刻单独复测 Cache `[经验]`。
3. 加电压的同时盯住温度，Ring 与核心抢散热，容易让核心先到线。

缓存电压不是"加了更稳"的保险，它只是把不稳定的边界往外推一点，代价是温度和封装功耗。

## 缓存不稳的标志

"频率不掉 + 温度不高"不等于稳定，完整判据见[稳定性验证](/principles/08-stability)。核心不稳和缓存不稳的表现不一样，可以按下面的表初步判断（下表是经验判据，不是官方错误分类） `[经验]`：

| 现象 | 更像核心不稳 | 更像缓存/Ring 不稳 |
|---|---|---|
| 满载蓝屏/重启 | 常见 | 也可能 |
| 空闲/轻载蓝屏、随机重启 | 较少 | 常见 |
| WHEA | Processor Core / Cache 都可能 | Cache / 互连相关更多 |
| 应用崩溃/闪退 | 高负载时 | 轻载、切换、加载时 |
| 一跑 FPU 就错 | 典型 | 也可能 |
| Cache 回 Auto 后恢复 | 否 | 是（关键判据） |

核心不稳通常在高负载、高电流时暴露；缓存不稳则经常在轻载、频率切换、程序加载这些瞬间露头。所以"跑一小时烤机没事，但开个网页就重启"这种症状，优先怀疑 Ring，而不是继续给核心加压。

WHEA 不一定是核心电压不够，也可能来自内存、缓存或 PCIe；定义与事件判读见[稳定性验证](/principles/08-stability)。

## 缓存怎么单独测试

缓存和核心是两套倍频、两套电压，所以必须分开验证。推荐顺序：

1. **先固定核心**：把核心倍频和电压调到已经验证稳定的状态，只动 Cache Ratio。
2. **只压缓存**：用 AIDA64 勾 `Stress cache` 单独跑 20–30 分钟 `[经验]`；再跑 `CPU + FPU + Cache` 组合。
3. **观察三类信号**：WHEA 计数、应用崩溃、以及空闲/轻载下的稳定性——缓存不稳常在轻载暴露。
4. **出问题先回退**：把 Cache 回 Auto 或降回原倍频复测，如果恢复就说明问题在 Cache。
5. **确实不够再加电压**：小幅加 `CPU Cache Voltage`（+0.01–0.02 V），每次只改一项。

**为什么缓存要单独测**：核心和 Cache 是两套倍频/电压，核心稳不代表 Ring 稳，Ring 不稳也不一定在 FPU 里暴露。只有把 Cache 单独跑一遍，才能把"核心的错"和"缓存的错"分开。

## Cache 回 Auto：最快的隔离手段

排查不稳定时，最省时间的动作不是加电压，而是**把变量减到最少**。标准隔离流程：

1. 内存回 JEDEC 默认档（或关掉 XMP），Cache 回 Auto。
2. 复现刚才的故障现象。
3. 如果故障消失，说明问题不在核心，逐项加回：先开 XMP，再把 Cache 拉回原倍频。

两个判断要点：

- **Cache 回 Auto 后恢复**，优先怀疑问题在缓存/互连 `[经验]`。
- **Cache 回 Auto 后照样崩**，问题更可能在核心、内存或供电，回到 [稳定性验证](/principles/08-stability) 的流程排查。

这条规则之所以有效，是因为 Cache 回 Auto 对桌面日常性能的影响通常不明显（ASUS 指南也建议超频时先让 cache 保持 Auto，以排除 Ring 因素）`[官方页]`，却能一次性排除一整类原因。

理解了 Ring 之后，还有一个和它共享封装资源的对象值得单独看：[集成显卡](/principles/05-igpu)。

## 本章要点

- Ring 连接核心、L3 缓存、内存控制器和核显，其频率就是 Cache Ratio；它决定的是访问延迟，不是算力。
- Cache Ratio 不必与核心同频，追求性能时放在"核心 −300 MHz"到"核心同频"之间；Ring 高于核心没有收益，只会更热。日常可以先 Auto。
- 缓存电压（`CPU Cache Voltage`）与核心电压是两套设置，作用于 uncore（含缓存/Ring）；Auto 起步，确认不稳后再以 0.01–0.02 V 为步进上调 `[经验]`。
- 缓存不稳更像"轻载蓝屏、随机重启、加载崩溃"；核心不稳更像"满载蓝屏、一跑 FPU 就错"。
- 缓存必须单独压（`Stress cache`）验证；**Cache 回 Auto 后故障消失**是判定缓存问题最快的判据。

# 缓存与 Ring

核心频率和内存调好之后，还有一条独立频率容易被忽略：缓存倍频，也就是 Ring。它不决定跑分，却常常是"核心明明没问题、机器偶尔蓝屏"的真正原因。

## Ring 连接什么

![图 1：Ring 环形总线把 CPU 核心、L3 缓存、内存控制器和核显串在一起，它的频率就是 Cache Ratio，等于 BCLK 乘倍频](/principles/04-ring.svg)

- Ring 是 CPU 内部的环状互连 `[Intel]`，核心访问 L3 和内存都要经过它。
- Ring 的频率就是 BIOS 里的 `CPU Cache Ratio`，算法和核心一样是 **BCLK × 倍频**：100 MHz 基准下 40x 就是 4000 MHz。
- 所以它决定的是访问延迟，不是算力：Ring 越高延迟通常越低 `[经验]`，但功耗和温度一起升，还会与核心抢散热。

## Cache Ratio 与核心频率的关系

核心倍频和缓存倍频是两套独立设置，**不必完全相同**，但也不能差太多。

> ASUS ROG 的 Haswell 指南大意：追求绝对性能时，Ring 保持在核心频率 300 MHz 以内就足够；Ring 高于核心频率没有性能收益，建议与 CPU 倍频同步，或最多低 300 MHz。`[官方页]`

| 设置 | 结果 |
|---|---|
| Ring = 核心 | 延迟最低，功耗与温度最高 |
| Ring = 核心 −300 MHz | 追求性能时的常见上限；日常可以先 Auto |
| Ring 远低于核心（如核心 47x、Ring 40x，差 700 MHz） | 多出明显的延迟差 `[经验]` |
| Ring > 核心（如核心 45x、Ring 47x） | 没有性能收益，只会更热 |

- 追求性能时，把 Ring 放在"核心 −300 MHz"到"核心同频"之间；日常可以先保持 Auto，确认核心稳定后再动它。
- 差 700 MHz 这种量级不划算，Ring 高于核心也没有收益，只会额外发热。

收益集中在缓存和内存的延迟上，不是所有应用都能感知——游戏帧数、加载时间比纯浮点跑分更容易体现出来。

## 缓存电压

缓存有自己的电压项，通常叫 `CPU Cache Voltage`，与核心电压是**两套独立设置**：

- 缓存电压作用于 CPU 的 uncore 部分（含缓存/Ring），不会自动帮核心加压，反之亦然；手册原文是 "voltage fed to the CPU uncores including its cache" `[手册]`。
- 不少主板的缓存电压提供 Auto / Manual / Offset 三种模式，Override 范围常见 0.001–1.920 V、Offset 范围常见 0.001–0.999 V `[手册]`。
- 具体到某一颗 CPU 需要多少缓存电压，没有官方推荐值，只能实测。
- 给电压的顺序和核心一样：Auto 起步；确认缓存不稳后再每次加 **0.01–0.02 V**，加完立刻单独复测 Cache `[经验]`，同时盯住温度。

缓存电压不是"加了更稳"的保险，它只是把不稳定的边界往外推一点，代价是温度和封装功耗。

## 缓存不稳的标志

![图 2：核心不稳与缓存不稳的症状分流，以及 Cache 回 Auto 的隔离流程](/principles/04-cache-isolation.svg)

核心不稳通常在高负载、高电流时暴露；缓存不稳则经常在轻载、频率切换、程序加载这些瞬间露头 `[经验]`。所以"跑一小时烤机没事，但开个网页就重启"，优先怀疑 Ring，而不是继续给核心加压。完整判据与 WHEA 判读见[稳定性验证](/principles/08-stability)。

## 缓存怎么单独测试

缓存和核心是两套倍频、两套电压，所以必须分开验证：

1. **先固定核心**：把核心倍频和电压调到已经验证稳定的状态，只动 Cache Ratio。
2. **只压缓存**：用 AIDA64 勾 `Stress cache` 单独跑 20–30 分钟 `[经验]`；再跑 `CPU + FPU + Cache` 组合。
3. **观察三类信号**：WHEA 计数、应用崩溃、以及空闲/轻载下的稳定性——缓存不稳常在轻载暴露。
4. **出问题先回退**：把 Cache 回 Auto 或降回原倍频复测，如果恢复就说明问题在 Cache。
5. **确实不够再加电压**：小幅加 `CPU Cache Voltage`（+0.01–0.02 V），每次只改一项。

核心稳不代表 Ring 稳，Ring 不稳也不一定在 FPU 里暴露；只有把 Cache 单独跑一遍，才能把"核心的错"和"缓存的错"分开。

## Cache 回 Auto：最快的隔离手段

排查不稳定时，最省时间的动作不是加电压，而是**把变量减到最少**（流程图见图 2 下半部分）：

- **Cache 回 Auto 后恢复**，优先怀疑问题在缓存/互连 `[经验]`。
- **Cache 回 Auto 后照样崩**，问题更可能在核心、内存或供电，回到[稳定性验证](/principles/08-stability)的流程排查。

这条规则之所以有效，是因为 Cache 回 Auto 对桌面日常性能的影响通常不明显（ASUS 指南也建议超频时先让 cache 保持 Auto，以排除 Ring 因素）`[官方页]`，却能一次性排除一整类原因。

理解了 Ring 之后，还有一个和它共享封装资源的对象值得单独看：[集成显卡](/principles/05-igpu)。

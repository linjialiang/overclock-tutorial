# 电压与供电

频率决定"想跑多快"，电压决定"能不能稳住"。但"电压"在 BIOS 里其实是三个不同的量：送进 CPU 的输入电压、CPU 自己请求的电压、以及真正加在核心上的电压。搞混这三层，是新手最常见的困惑来源。

这一章先把三层电压拆开，再讲四种电压模式只作用于其中一层、LLC 与掉压的关系，最后把功耗与温度这两道墙理清楚。

## 三层电压：VCCIN、VID 与 Vcore

| 名称 | 谁产生 | 含义 |
|---|---|---|
| VCCIN | 主板 VRM | 送给 CPU 的输入电压 |
| VID | CPU 自己 | 按倍频和负载"请求"的电压 |
| Vcore | CPU 内部调压器 / 主板 | 真正加在核心上的电压 |

一句话区分：**VCCIN 是"送进 CPU 的电"，VID 是"CPU 说自己要多少"，Vcore 是"核心真正拿到多少"。**

这三层里，**只有 Vcore 有 Auto / Manual / Offset / Adaptive 四种控制模式**；VCCIN 是独立设置，VID 是 CPU 自己的请求值，都不是"模式"。这一点下面会展开。

### VID 是什么

每颗 CPU 出厂时都会写入自己的电压识别值（VID），按这颗芯片的特性和设计余量给定，服务于"默认频率稳定"，**不等于这颗 U 在超频频率下的最低可用电压** `[Intel]`。

所以会出现两种情况：

- 体质好的样品，同一频率需要的电压可能低于 VID——这是正常的，但 VID 表不会帮你自动降下来。
- 体质一般的样品，超频后需要的电压高于 VID，这就是"要加电压"的来源。

## 两种架构：FIVR 与主板直供

Vcore 由谁生成，不同平台不一样，这直接决定了 LLC 的作用点。

**片上调压（FIVR）**

- 调压器做进了 CPU 内部，主板只提供一路较低的输入电压（这一代典型约 1.8 V），再由片内调压器生成 Vcore `[官方页]`。
- 因此 LLC 作用在 VCCIN 这一侧，对 Vcore 是**间接**影响：主板补的是输入，输出还要经过片内调压器。

**主板直供**

- 多数现代平台由主板 VRM 直接生成 Vcore。
- LLC 对 Vcore 的影响更直接，档位变化能立刻从读数上看出来。

无论哪种架构，"CPU 请求值"和"实际加到核心上的值"都是两件事。读数对不上时，先确认自己在看哪一层。

## 四种电压模式：只作用于 Vcore

先明确范围：这四种模式**只作用于 Vcore 这一层**，也就是"核心最终拿到多少电压"的控制方式，不是三层电压都有这四种模式。

| 电压层 | 是否有这四种模式 | 说明 |
|---|---|---|
| VCCIN | 否 | 独立项（CPU Input Voltage），通常只有 Auto / 固定值，不跟随 VID |
| VID | 否 | 它不是"模式"，而是 CPU 按倍频/负载查表得到的**请求值**，是这四种模式要处理的对象 |
| Vcore | 是 | Auto / Manual / Offset / Adaptive 都在决定"最终 Vcore 怎么来" |

换句话说：**VID 是 CPU 说的话，四种模式是 BIOS 决定"听不听、怎么改"。**

| 模式 | 具体指什么 | 空闲电压 | 满载电压 | 能否低于默认请求 | 适合谁 |
|---|---|---|---|---|---|
| Auto | BIOS 不干预，直接采用 CPU 的 VID 请求 | 跟随 VID | 跟随 VID | — | 不折腾 |
| Manual | BIOS 用一个固定值**覆盖** VID，不看负载与倍频 | 固定值 | 固定值 | 能 | 验证体质、固定工作点 |
| Offset | 在 VID 基础上**加/减一个固定偏移**，整条曲线平移 | VID ± 偏移 | VID ± 偏移 | 能（负号） | 想保留空闲降压 |
| Adaptive | 非 Turbo 区间跟随 VID，Turbo 区间用 Additional Turbo 目标（可再叠加 Offset） | 跟随 VID | 随 Turbo 目标与 Offset 变化 | 取决于实现 | 想兼顾空闲与满载 |

### 几个容易混的点

- "Manual 固定"固定的是 **Vcore**，不是 VCCIN；VCCIN 仍然是另一个独立设置。
- "Offset"改的是 **VID 的偏移量**，所以空闲和满载会一起变；负偏移能降压，正偏移能加压。
- "Adaptive"通常只改 Turbo 档，空闲仍跟随 VID；它的 Additional Turbo 是"Turbo 档目标值"，最终是多少要看 Total 显示。
- 不同主板/BIOS 的命名不完全一样。同一块板子的**手册和实机 BIOS 也可能对不上**：手册列两三种模式、实机多一种的情况很常见。更要注意的是，某些电压页面（例如核显电压）上的 Adaptive / Additional Turbo 属于另一个对象，不要和核心电压混在一起。

### 场景怎么选

| 场景 | 首选 | 原因 |
|---|---|---|
| 常规超频，目标 ≥ VID | **Adaptive** | 保留空闲降压，厂商也常把它列为超频首选 |
| 目标 < VID（大雕低压） | **负 Offset** | 整条曲线下移，保留空闲降压 |
| 只验证某个电压稳不稳 | **Manual** | 固定值，排除变量 |
| 不想折腾 | **Auto** | 默认最稳 |

几点补充：

- **厂商对 Adaptive 的定位**：Adaptive 只影响 Turbo 倍频档，不影响空闲/轻载 Vcore；想保留动态降压时，有厂商把它列为该平台超频的首选 `[官方页]`。
- **Adaptive 怎么给电压**：它以主板预设的倍频-电压曲线为基础，把曲线高端（Turbo 档）设到目标值，Offset 再让整条曲线上下平移；部分厂商手册写明 `Total = Offset + Additional Turbo` `[官方页]`。这套机制的方向是"抬高上限"，不是"压到最低"。
- **低于 VID 时**：官方没有承诺 Adaptive 能低于 VID。实际调校中经常出现"设定值低于 VID、系统读数仍停在 VID 附近"的情况 `[经验]`，这时应改用负 Offset 或 Manual。
- **判断顺序**：BIOS 的 Total 是否等于目标 → 系统里读的是 Vcore 还是 VID → 用 Manual 同电压做对照。

> **要点**：模式只决定"电压怎么给"，不决定"能给多低"。能不能低于默认 VID，要看具体 BIOS 实现；手册没写的部分，只能实测。

## 供电与保护各管什么

调电压之前，先分清每个机制管的是哪一层，否则很容易"用错工具"。

| 机制 | 作用层级 | 作用 |
|---|---|---|
| LLC | 主板外部供电 | 补偿负载升高时的电压跌落 |
| Current Capability | 主板 VRM | 过流保护余量，不是功耗墙 |
| PL1 / PL2 | CPU 封装 | 长时间/短时间功耗上限 |
| Tjmax / TCC | CPU 核心 | 约 100 °C 触发降频保护 `[Intel]` |

判断顺序：**先看频率有没有掉（节流），再看温度，最后才看电压**。不要一看到电压波动就去升 LLC。

## 功耗 ≈ 电压² × 频率

核心功耗近似与 **电压的平方 × 频率** 成正比。这个公式解释了很多"反直觉"的现象：

- 电压降低约 3%（例如 1.30 V → 1.26 V 这种量级），理论功耗降约 6%，但频率不变时稳定性余量也在下降。
- 频率提升 100 MHz，往往需要 20~50 mV 的电压补偿，功耗上升比频率更快。
- 温度不是线性：散热器接近上限时，每加 10 W 温度可能跳 3~5 °C。

所以"频率优先"的代价通常不是多一点点热，而是**热得更快、余量更小**。

## Vdroop 与 LLC 的取舍

CPU 满载时电流突然增大，电压会瞬间下跌，这叫 Vdroop（掉压）。

- 掉压本身是正常现象，CPU 设计时已经考虑。
- LLC 的作用是让主板在负载升高时多补一点电压，减少掉压。
- LLC 太高：空载/轻载电压偏高，负载切换时可能过冲。
- LLC 太低：满载电压跌太多，可能不稳。

判断标准不是"读数漂不漂亮"，而是"频率有没有掉、有没有错误"。掉压但频率不降、无 WHEA，可以不动。

**LLC 是补偿，不是加压**。把它当成"稳不住的万能药"，只会把风险从"满载掉压"换成"瞬态过冲"。

## 功耗墙、温度墙与电流墙

频率掉了，先别急着加电压——先搞清楚是被哪面墙挡住的：

- **功耗墙**：Package Power 长时间顶在 PL1/PL2 附近，频率掉 → 是功耗限制。
- **温度墙**：核心温度接近 Tjmax（约 100 °C），频率掉 → 是散热限制。
- **电流墙**：IA Current 顶到限制，频率掉 → 是电流/VRM 限制。
- **都不是**：频率稳定、温度不高、功耗不高 → 当前设置还有余量。

先定位是哪面墙，再决定加电压、换散热还是降频，不要盲目加电压。分不清"核心不稳"和"节流"时，可以看[稳定性验证](/principles/08-stability)。

## 本章要点

- 三层电压各归各：VCCIN 是主板送的输入，VID 是 CPU 按倍频/负载请求的值，Vcore 是核心实际拿到的。
- 只有 Vcore 有 Auto / Manual / Offset / Adaptive 四种模式；VCCIN 是独立设置，VID 不是模式。
- FIVR 架构下 LLC 作用在 VCCIN 侧，对 Vcore 只是间接影响；主板直供架构下 LLC 对 Vcore 更直接。
- 功耗近似正比于 V² × f，所以加电压的代价比加频率更快；先看频率有无节流，再看温度，最后才看电压。
- 掉压是正常现象，LLC 只做补偿；拉满会带来瞬态过冲。判断标准是频率和错误，不是读数。

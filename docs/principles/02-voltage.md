# 电压与供电

频率决定"想跑多快"，电压决定"能不能稳住"。但"电压"在 BIOS 里其实是三个不同的量：送进 CPU 的输入电压、CPU 自己请求的电压、以及真正加在核心上的电压。搞混这三层，是新手最常见的困惑来源。

## 三层电压：VCCIN、VID 与 Vcore

![图 1：主板 VRM 送出 VCCIN（这一代典型约 1.8 V），经片内调压器或主板 VRM 生成 Vcore；VID 是 CPU 提出的请求值，不是实际加在核心上的电压](/principles/02-voltage-layers.svg)

| 名称 | 谁产生 | 含义 |
|---|---|---|
| VCCIN | 主板 VRM | 送给 CPU 的输入电压 |
| VID | CPU 自己 | 按倍频和负载"请求"的电压 |
| Vcore | CPU 内部调压器 / 主板 | 真正加在核心上的电压 |

一句话区分：**VCCIN 是"送进 CPU 的电"，VID 是"CPU 说自己要多少"，Vcore 是"核心真正拿到多少"。**

这三层里，只有 Vcore 是"核心最终拿到多少电压"的控制对象；但**具体有几种模式取决于主板和 BIOS**：例如部分 Z97 主板的 CPU Core Voltage 只有 Auto / Manual / Offset 三种，CPU Graphics Voltage 才提供 Auto / Manual / Offset / Adaptive 四种 `[手册]`。VCCIN 是独立设置，VID 是 CPU 自己的请求值，都不是"模式"。

每颗 CPU 出厂时都会写入自己的电压识别值（VID），按这颗芯片的特性和设计余量给定，服务于"默认频率稳定"，**不等于这颗 U 在超频频率下的最低可用电压** `[Intel]`。所以：体质好的样品，同一频率需要的电压可能低于 VID——但 VID 表不会帮你自动降下来；体质一般的样品，超频后需要的电压高于 VID，这就是"要加电压"的来源。

## 两种架构：FIVR 与主板直供

Vcore 由谁生成，不同平台不一样，这直接决定了 LLC 的作用点。

- **片上调压（FIVR）**：调压器做进了 CPU 内部，主板只提供一路较低的输入电压（这一代典型约 1.8 V），再由片内调压器生成 Vcore `[官方页]`。因此 LLC 通常作用在 VCCIN 一侧，对 Vcore 是**间接**影响：主板补的是输入，输出还要经过片内调压器。这是架构推断，手册只写到"LLC 影响 CPU 供电电压" `[手册]`。
- **主板直供**：多数现代平台由主板 VRM 直接生成 Vcore，LLC 对 Vcore 的影响更直接，档位变化能立刻从读数上看出来。

无论哪种架构，"CPU 请求值"和"实际加到核心上的值"都是两件事。读数对不上时，先确认自己在看哪一层。

## 电压模式：先确认作用于哪一层

![图 2：Auto 全程跟随 VID、Manual 用固定值覆盖、Offset 让曲线整体平移、Adaptive 在 Turbo 区间抬起；能低于 VID 的只有 Manual 与负 Offset，且模式数量随主板变化](/principles/02-voltage-modes.svg)

这些模式都只作用于"某一层电压"，不是三层通用。最常见的是 Vcore，但核显电压、缓存电压也可能有各自的模式；数量与命名因主板/BIOS 而异，部分主板的核心只有前三种。

| 电压层 | 是否有模式 | 说明 |
|---|---|---|
| VCCIN | 否 | 独立项（CPU Input Voltage），通常只有 Auto / 固定值，不跟随 VID |
| VID | 否 | 它是 CPU 按倍频/负载查表得到的**请求值**，是这些模式要处理的对象 |
| Vcore | 视主板而定 | Auto / Manual / Offset / Adaptive 中的若干种，决定"最终 Vcore 怎么来" |

换句话说：**VID 是 CPU 说的话，这些模式是 BIOS 决定"听不听、怎么改"。**

- "Manual 固定"固定的是 **Vcore**，不是 VCCIN；VCCIN 仍然是另一个独立设置。
- "Offset"改的是 **VID 的偏移量**，所以空闲和满载会一起变；负偏移能降压，正偏移能加压。
- "Adaptive"通常只改 Turbo 档，空闲仍跟随 VID；它以主板预设的倍频-电压曲线为基础，把曲线高端设到目标值，部分厂商手册写明 `Total = Offset + Additional Turbo` `[手册]`。这套机制的方向是"抬高上限"，不是"压到最低"。
- 不同主板/BIOS 的命名不完全一样，**手册和实机 BIOS 也可能对不上**：手册列两三种、实机多一种的情况很常见。某些电压页面（例如核显电压）上的 Adaptive / Additional Turbo 属于另一个对象，不要和核心电压混在一起。

| 场景 | 首选 | 原因 |
|---|---|---|
| 常规超频，目标 ≥ VID | **Adaptive** | 保留空闲降压 |
| 目标 < VID（大雕低压） | **负 Offset** | 整条曲线下移，保留空闲降压 |
| 只验证某个电压稳不稳 | **Manual** | 固定值，排除变量 |
| 不想折腾 | **Auto** | 默认最稳 |

是否把 Adaptive 列为超频首选，因厂商和主板而异，需要查对应手册，不能当成所有平台的统一推荐。

> **要点**：模式只决定"电压怎么给"，不决定"能给多低"。官方没有承诺 Adaptive 能低于 VID；实际调校中经常出现"设定值低于 VID、系统读数仍停在 VID 附近" `[经验]`，这时应改用负 Offset 或 Manual。判断顺序是：BIOS 的 Total 是否等于目标 → 系统里读的是 Vcore 还是 VID → 用 Manual 同电压做对照。

## 供电与保护各管什么

调电压之前，先分清每个机制管的是哪一层，否则很容易"用错工具"。

| 机制 | 作用层级 | 作用 |
|---|---|---|
| LLC | 主板外部供电 | 补偿负载升高时的电压跌落 |
| SVID | CPU 与外部 VRM 之间 | CPU 向 VRM 请求电压的接口；超频时通常保持 Enabled，部分主板可 Override |
| Current Capability | 主板 VRM | VRM 电流/供电能力上限，不是 CPU 功耗墙 |
| PL1 / PL2 | CPU 封装 | 长时间/短时间功耗上限（Intel 平台） |
| Tjmax | CPU 核心 | 结温上限；Intel 4th Gen 桌面约 100 °C，其他平台以规格为准 `[Intel]` |
| TCC | CPU 核心 | 接近 Tjmax 时降频/降电压的热控制机制，不是温度点 |

## 功耗 ≈ 电压² × 频率

核心功耗近似与 **电压的平方 × 频率** 成正比。这个公式解释了很多"反直觉"的现象：

- 电压降低约 3%，理论功耗降约 6%，但频率不变时稳定性余量也在下降。
- 频率提升 100 MHz，通常需要 20~50 mV 的电压补偿 `[经验]`，功耗上升比频率更快。
- 温度不是线性：散热器接近上限时，每加 10 W 温度可能跳 3~5 °C `[经验]`。

所以"频率优先"的代价通常不是多一点点热，而是**热得更快、余量更小**。

## 掉压、三道墙与 LLC

![图 3：频率掉了先看是哪个读数顶住——Package Power 到顶是功耗墙、温度接近 Tjmax 是温度墙、IA Current 到顶是电流墙；满载瞬间掉压属正常现象，LLC 只负责补偿](/principles/02-power-walls.svg)

- **功耗墙**：Package Power 长时间顶在 PL1/PL2 附近，频率掉 → 是功耗限制，先降频或放宽上限。
- **温度墙**：核心温度接近 Tjmax（Intel 4th Gen 桌面约 100 °C；其他平台看规格 `[Intel]`），频率掉 → 是散热限制。
- **电流墙**：IA Current 顶到限制，频率掉 → 是电流/VRM 限制（Intel 平台的常见读数名）。
- 三面墙都不是：频率稳定、温度不高、功耗不高 → 当前设置还有余量。

Vdroop 是 CPU 满载瞬间电流突增导致的正常掉压，CPU 设计时已经考虑；LLC 让主板在负载升高时多补一点电压。

- LLC 太高：空载/轻载电压偏高，负载切换时可能过冲 `[经验]`。
- LLC 太低：满载电压跌太多，可能不稳 `[经验]`。

判断标准不是"读数漂不漂亮"，而是"频率有没有掉、有没有错误"。掉压但频率不降、无 WHEA，可以不动。**LLC 是补偿，不是加压**：把它当成"稳不住的万能药"，只会把风险从"满载掉压"换成"瞬态过冲"。分不清"核心不稳"和"节流"时，看[稳定性验证](/principles/08-stability)。

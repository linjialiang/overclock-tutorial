# 超友案例投稿模板与资源要求

这是「超友案例」的第一篇。它不是案例，而是投稿时必须准备的材料清单和写作模板：照着填，读者才能判断你的结果是否可信、能否复现。

## 1. 使用方式

- 复制本页为 `docs/cases/NN-平台简称.md`，一人一章；同一人多次投稿合并更新，不另开新章。
- 按顺序填写；没有做的项目写"未测试"，不适用的写"不适用"，不要留空。
- 截图放到 `docs/public/cases/NN-平台简称/`，文件名用英文小写和连字符。
- 数据必须来自你自己的机器；引用别人的结果时，明确标注来源。

## 2. 平台信息

| 项目 | 填写内容 |
|---|---|
| CPU | 型号、核心/线程、默认频率、TDP |
| 主板 | 型号、芯片组、BIOS 版本 |
| 内存 | 型号、容量、条数、标称频率、颗粒（已知时） |
| 显卡 | 核显型号或独显型号 |
| 电源 | 型号、额定功率、80Plus 等级 |
| 散热 | 散热器型号、风扇数量与尺寸 |
| 机箱风道 | 进风扇、出风扇的数量与尺寸 |
| 室温 | 测试时的环境温度 |
| 操作系统 | 版本与电源计划 |

## 3. 目标与结果

| 项目 | 填写内容 |
|---|---|
| 目标 | 想达到的频率/电压，或想解决的问题 |
| 实际 | 最终稳定频率、电压、缓存频率、内存频率 |
| 测试 | 用了哪些负载、各跑多久 |
| 温度 | 满载最高温度、空闲温度 |
| 功耗 | 满载封装功耗（平均/最大） |
| 结论 | 通过 / 降级后通过 / 失败，以及最终日常设置 |

## 4. BIOS 设置

只填实际改动过的项；保持默认的写"默认"。涉及电压的项要写清模式和数值。

| 项目 | 填写内容 |
|---|---|
| BCLK | 100 MHz 或实际值 |
| CPU Core Ratio | 全核倍频，或逐核设置 |
| CPU Core Voltage | 模式（Auto / Manual / Offset / Adaptive）+ 数值 |
| Offset Mode Sign / Offset | 符号与数值（如有） |
| LLC | 档位或 Auto |
| CPU Cache Ratio | Min / Max |
| CPU Cache Voltage | 模式 + 数值 |
| VCCIN | Auto 或固定值 |
| 内存 | XMP 开关、频率、DRAM Voltage、主要时序 |
| VCCSA / VCCIO | Auto 或固定值 |
| 功耗/电流限制 | 实际值或"不限制" |
| 节能 | EIST / C-States 是否保留 |

## 5. 必交截图

| 截图 | 必须包含的信息 |
|---|---|
| HWiNFO 传感器页（满载） | VID、Vcore、核心频率、封装温度、封装功耗 |
| AIDA64 稳定性测试页 | 测试类型、已运行时长、当前温度/频率 |
| CPU-Z 内存/SPD 页 | 内存频率、时序、通道、条数 |
| BIOS 关键页 | 电压模式、倍频、内存电压 |
| 可选：空闲 | 空闲频率、电压、温度、功耗 |
| 可选：内存测试 | 测试类型、时长、DRAM 电压 |

截图要求：原图、不裁掉关键列、时间与测试对应；不要用拍照代替截图，除非 BIOS 无法截图。

## 6. 测试记录

至少填一行满载测试；做过多种负载就逐行列出。

| 测试 | 工具/设置 | 时长 | 结果 | 最高温度 | 备注 |
|---|---|---|---|---|---|
| CPU 满载 | AIDA64 Stress CPU | 30 分钟 | 通过/失败 |  |  |
| FPU 满载 | AIDA64 Stress FPU | 10 分钟 | 通过/失败 |  |  |
| 缓存 | AIDA64 Stress cache | 20 分钟 | 通过/失败 |  |  |
| 内存 | AIDA64 Stress system memory | 1 小时 | 通过/失败 |  |  |
| 组合 | CPU + FPU + Cache + Memory | 30 分钟 | 通过/失败 |  |  |
| 真实应用 | 游戏/渲染/编译 |  |  |  |  |

判定标准：无蓝屏、无重启、无 WHEA、无应用崩溃、频率不异常掉落。只有"能开机"不算通过。

## 7. 结论与踩坑

- **哪些设置生效、哪些没生效**：用数据对比，例如"改了电压但 Vcore 没变"。
- **失败点**：蓝屏代码、WHEA 类型、在哪个测试/应用里出错。
- **最终日常设置**：频率、电压、缓存、内存、LLC。
- **给别人的建议**：这台平台上先改什么、不要改什么、哪些值不要照抄。

## 8. 来源标注

| 标记 | 用途 |
|---|---|
| `[Intel]` | Intel 官方规格或数据表 |
| `[手册]` | 主板官方手册，尽量写页码或章节 |
| `[官方页]` | 厂商产品页、官方指南 |
| `[本机]` | 你自己的实测数据 |
| `[经验]` | 社区经验值，不是官方保证 |

官方规格给链接或页码；经验值必须标 `[经验]`，不要写成官方结论。

## 9. 文件与排版

- 文件名：`NN-平台简称.md`，例如 `01-4790k-z97ar.md`。
- 图片目录：`docs/public/cases/NN-平台简称/`。
- 标题只用一个 `#`，章节用 `##`，小节用 `###`。
- 数据优先用表格；长段落拆成短段；结论放前面，细节放后面。
- 不写没有数据支撑的主观判断；"我觉得"不能代替测试结果。

## 10. 最小提交清单

- ☐ 平台信息完整（第 2 节）
- ☐ 目标、实际、结论清楚（第 3 节）
- ☐ BIOS 设置完整（第 4 节）
- ☐ 满载 HWiNFO + AIDA64 截图（第 5 节）
- ☐ CPU-Z 内存/SPD 截图
- ☐ 至少一项满载测试记录，含时长与温度（第 6 节）
- ☐ 踩坑与最终设置（第 7 节）
- ☐ 官方规格与经验值分开标注（第 8 节）

满足以上八项，案例就可以合并进站点。
